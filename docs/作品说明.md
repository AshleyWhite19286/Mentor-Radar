# 导师雷达：从近期论文找到科研起点

## 创作背景

低年级学生在第一次了解实验室、联系老师时，常遇到两层信息差：不知道老师近期研究什么，也难以读懂专业论文。部分官网个人页只列较早的代表成果，学生难以把概括性的研究方向与真实研究问题对应起来。

导师雷达把学院师资导航、近期论文证据和个性化学习建议放在一起，让学生先理解研究，再判断自己的兴趣和基础是否适合进一步接触。

## 核心功能

网站保留学院目录式浏览体验，展示教师真实姓名、照片、职称和所属机构。已按上海交大集成电路学院（信息与电子工程学院）官网的12个分类同步全部人员。平台人员不自动视为招生导师。

每个机构有官方背景、面向初学者的解释、近期研究观察、建议基础和样本覆盖说明。机构观察只来自当前样本，不把一位老师的方向当作全所定位。

教师页用三列展示论文：基本信息、摘要及关键词、通俗解读与入门。解读说明问题和方法，并区分理解论文、局部复现和真正开展研究所需的基础。每篇有一个明确标为AI建议的小任务。

个人匹配根据年级、兴趣、课程、编程经验、时间与目标，给出最多3位推荐、具体证据、基础差距和四周计划。问答助手可继续围绕指定教师或论文解释概念。

学生可以用自己的模型Key补充单个教师，核对身份及论文后保存到本机。新证据可以触发机构研究观察的修改建议，但使用者确认前不会改变现有简介。建议包含前后对照、修改理由和证据链接，并支持恢复旧版。

## 智能体实现

系统采用Next.js、TypeScript、Tailwind CSS及SQLite。智能体在有限步骤内理解问题、选择相关教师、读取论文证据、生成结果并检查字段和引用。使用Chat Completions兼容接口，不依赖模型一定支持原生工具调用。

导师添加会调用公开页面读取、作者候选检索、学术论文检索和摘要解读。结构化结果最多修复一次；不存在的来源引用、错误教师ID或错误论文归属会被拒绝。执行界面显示实际完成的步骤，不展示模型内部推理。

## 操作指南

1. 安装Node.js 22.13以上版本，执行`npm ci`与`npm run dev`，打开`http://127.0.0.1:3000`。
2. 浏览导师名录或研究所导览，无需Key。用姓名或方向搜索，点击人员卡片进入详情。
3. 阅读三列论文表，展开原始摘要、入门路线及研究边界，点击链接核对来源。
4. 在模型设置中填写自己的学校Key，获取模型列表并测试连接。当前页面关闭或刷新后凭证清除。
5. 在“我的科研起点”填写个人基础，生成推荐与四周路径；或对教师、论文继续提问。
6. 点击“补充导师”，输入个人页或粘贴资料，选择正确作者并逐篇确认论文。缺失资料可用DOI及原始摘要补充。
7. 新增教师后到对应机构页查看简介修改建议，比较前后内容与来源，选择采用或保留原文；已采用版本可恢复。

## 效果与验证

预置12个机构、273位官网目录人员和56篇已核验的近期论文元信息。当前43篇具有公开摘要及预置解读，其余13篇明确标为待补摘要；其余目录人员的论文尚待作者身份核验；AEMD深度样本当前仅核实1篇近期论文，已按36个月窗口如实标注。

已完成20项核心及工作流测试、4项浏览器端到端验收，覆盖窗口规则、去重、日期边界、引用、凭证不落库、教师导入、个性化匹配、证据问答、任务失败、简介确认和恢复，以及桌面和手机布局。生产构建与TypeScript检查通过。模型输出使用模拟返回验证；真实学校API仍需个人Key联调。

## 已知边界与后续阶段

学术索引会漏收、误归属或混合同名作者，本项目已排除可识别的错误，但不承诺收录全部最新发表成果。首次在线时间未确认的记录保留备注。没有全文时只解读摘要，不补写不存在的实验细节。

当前未收录可靠的个人体验反馈，不生成口碑分数。研究主题不能证明正在招生、在研项目或导师管理风格。部分机构背景来源为覆盖多个单位的学院建设报道，页面保留这一范围。

目录资料通过`npm run data:directory:all`重新同步；新同步人员先展示可追溯的官网身份资料，近期论文会在作者身份核验后进入个人详情。
